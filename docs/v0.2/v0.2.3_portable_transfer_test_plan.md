# V0.2.3 個人資料搬運：驗收紀錄

> 驗收日期：2026-09-19
>
> 結果：匯出後刪除一筆資料，再匯入原搬運檔，確認只補回主資料區缺少的新 ID；既有資料未被覆蓋。使用者回報測試 OK。

此功能只搬運 JobCheck 的個人資料（公司、職缺、應徵及內嵌事件），不會從 104 或其他網站抓職缺。匯出檔副檔名為 `.jobcheck.json`，內含 `format_version: "0.2"`、筆數與 SHA-256 校驗碼。校驗碼用於發現檔案損壞，**不是加密或身分驗證**；檔案包含個人求職紀錄，請勿公開上傳。

## 人工驗收

1. 在有測試資料的裝置 A 開啟 JobCheck，切到「個人」資料區，點「資料搬運」→「匯出」。確認畫面顯示完整檔案路徑與公司／職缺／應徵筆數，原本的資料仍可讀取。預設輸出到「文件/JobCheck/Exports」，每次使用新檔名，不覆蓋先前檔案。
2. 在裝置 B 安裝同版本 JobCheck，切到「個人」資料區，將裝置 A 的檔案複製到 B，點「選擇檔案」選取 `.jobcheck.json`。畫面應列出新增的公司／職缺／應徵／事件筆數；確認是自己的資料後才按「匯入」。取消選檔應保持原畫面、不匯入。B 可以是空白，也可以已含先前同步的資料。
3. 匯入成功後關閉面板、按「Load」，逐項檢查公司／職缺、應徵狀態、事件歷程與分析頁筆數。重新啟動程式再確認資料仍在。
4. 再次選擇同一檔，預期新增筆數為零，匯入按鈕停用；既有資料不得改變。以 A 有四筆、B 已有其中三筆的資料測試，預期只加入第四筆，不複製前三筆。切到 Demo 資料區時，匯出及匯入按鈕應不可用。
5. 讓 A、B 同一 ID 的既有公司／職缺／應徵內容不同，再選擇 A 的檔案：預期顯示衝突，整批不寫入、不覆蓋 B 的版本。來源檔含別人的資料時，使用者不可將其當作自己的同步檔；目前檔案格式尚無個人資料身分識別。
6. 複製搬運檔後任意修改 JSON 內容但不更新校驗碼，預覽應拒絕。缺檔、錯誤副檔名、不支援的 `format_version`、重複 ID 或失效的關聯資料也應拒絕。

## 安全邊界

- 空白個人資料區仍使用完整還原；已有資料時只把新 ID 的實體檔加入，重複且內容相同的略過，同 ID 內容不同的整批拒絕。既有檔案及 `trash` 不改動。
- 現階段「新紀錄」限新公司、新職缺、新應徵及其事件。既有應徵後續新增事件、改變狀態或編輯內容，都視為同 ID 衝突；尚未提供逐欄位／逐事件合併，以免覆蓋兩端各自更新的資料。
- 同步先寫同層暫存目錄並重新讀取驗證，再依公司、職缺、應徵順序加入新檔。每步都不覆蓋既有檔案；可捕捉的寫入失敗會回復本次新增檔。突然斷電時可能留下部分新增檔，但不會刪除舊資料，再次同步會補齊未新增的檔案。
- Demo 資料與個人資料分離；使用者應先自行備份原裝置，再處理搬運檔。
- 本次已驗證同一裝置的增量差異流程；真正跨裝置的路徑、權限與檔案複製仍需在第二個安裝環境驗收。自動測試只使用合成資料。

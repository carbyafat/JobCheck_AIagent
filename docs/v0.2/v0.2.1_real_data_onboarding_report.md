> 完成日期：2026-09-15

> Unity：2022.3.62f3 LTS

> 前一版封版基準：265 passed、0 failed

## 1. 版本目標

V0.2.1 的目標不是串接或爬取求職平台，而是讓使用者能把真實職缺安全地整理進 JobCheck，並在日常求職過程中持續更新：

```text
真實職缺內容
    ↓ 人工整理與輸入
personal_data/（不進 Git）
    ↓
新增／編輯職缺
    ↓
補登應徵事件與日期
    ↓
事件歷程與目前狀態
```

這一版延續 V0.2.0 的 Domain 與 Repository，不另外建立一套只供真實資料使用的格式。

## 2. 已完成範圍

### 2.1 Demo 與個人資料隔離

- 新增 Demo／個人資料模式，並可從總攬頁切換。
- Demo 繼續讀取版本控制內的 `data/`。
- 個人資料寫入本機 `personal_data/`。
- `personal_data/` 整個目錄由 `.gitignore` 排除，避免公司名稱、職缺內容與應徵歷程被提交。
- 第一次切換到個人資料時才建立目錄；一般讀取不會產生副作用。

### 2.2 真實職缺輸入

新增與編輯表單已能處理：

- 公司、職缺名稱、部門、職務類別與收錄日期。
- 來源平台、來源網址及完整職缺原文。
- 薪資類型、週期、上下限、幣別與原始薪資文字。
- 工作地點、工作模式、聘僱形式與工作時間。
- 經驗、學歷、工作內容、工具技術與技能能力。
- 受控的職缺標籤與風險標記。

薪資類型、薪資週期、工作模式與聘僱形式使用受控選項；Tag 與 RiskFlag 使用可複選介面；工作內容與技能需求使用多行輸入，降低自由文字格式漂移。

### 2.3 應徵事件與歷史日期

- 新事件可以輸入實際發生日期，支援事後補登。
- 日期留空時代表現在，不要求使用者虛構精確時間。
- 日期輸入與文字備註共用整合式對話框，依事件切換標題、說明和輸入欄位。
- 本人放棄等需要文字原因的操作使用多行文字輸入。
- Reducer 仍負責依事件歷程推導目前階段，並阻止不安全的事件順序。
- 同一職缺再次投遞時建立新的 Application，保留前一次應徵關係。

### 2.4 UI 實用性調整

- 新增與編輯表單改為有分區標題與欄位名稱的版面。
- 長文字欄位改為多行，方便輸入與回看。
- 下拉選單的目前值與展開選項提高字體大小與列高。
- 列表中的公司／職缺使用主要字級，薪資／狀態使用次要字級。
- 詳細頁優先顯示結構化薪資；資料不足時才顯示原始薪資文字。
- TextMesh Pro 使用 Yozai-Light SDF 顯示中文。

### 2.5 個人資料刪除

- 刪除只開放於個人資料模式，Demo 資料保持唯讀保護。
- 刪除職缺前顯示確認視窗。
- 職缺及其 Application／ApplicationEvent 不直接永久刪除，而是一起移到 `personal_data/trash/`。
- 移動失敗時不回報成功，避免只刪除部分關聯資料。

目前尚未提供垃圾桶瀏覽與 UI 還原；需要時仍可從本機檔案復原。

### 2.6 中文錯誤訊息

- 新增集中式 `ValidationErrorLocalizer`。
- 分別支援 JobPosting、Application、ApplicationEvent 與 Reducer issue 四種 enum。
- 目前 76 個 Domain 錯誤代碼都有繁體中文訊息。
- 同名錯誤會依資料種類顯示不同內容，例如職缺、應徵與事件的 `MissingId`。
- Command Service 與 Repository 不再直接把上述 enum 名稱當成使用者訊息。
- Console 仍保留儲存層錯誤代碼與欄位路徑，供開發除錯。

## 3. 實際使用驗收

V0.2.1 已使用個人真實求職資料持續操作數日。這段驗收不是一次性的固定測試，而是實際使用新增、編輯與追蹤功能，再將遇到的問題回饋到 UI 與驗證規則。

已實際碰觸的情境包括：

- 長篇中文職缺內容與中文字形顯示。
- 薪資上下限、面議與資料缺漏。
- 多個 Tag／RiskFlag 與錯誤輸入。
- 新增、編輯、重新載入及詳細頁顯示。
- 收藏、有興趣、已投遞、公司已讀、追蹤日期與事件日期。
- 無後續回覆的真實求職情境。
- 個人職缺刪除與 Demo 禁止刪除。

不是每筆應徵都會自然走完整條流程；沒有收到後續本身就是有效的求職結果，因此不要求以假資料補齊 Offer、面試或拒絕事件。

## 5. 資料與版本控制安全

- `data/` 只保存虛構 Demo 與 migration 證據。
- `personal_data/` 保存真實求職資料並由 Git 忽略。
- UI 動態產生的 Demo UUID JSON 預設仍不會自動加入版本控制。
- 個人資料不應出現在測試 fixture、截圖文件或完成報告中。
- 封版前仍應執行一次 `git status --ignored`，確認個人資料沒有被意外追蹤。

## 6. 已知限制

以下項目不阻擋 V0.2.1 完成：

- 真實職缺目前仍由使用者人工輸入，沒有平台自動匯入。
- 垃圾桶目前沒有瀏覽與還原 UI。
- 很多公司在投遞後沒有回覆，因此部分事件路徑只能隨實際求職進度持續驗證。
- `AllJobPage` 與 `Panel_JobDetail` 仍承擔較多 UI 協調責任。
- 獨立 Build 的資料存放路徑仍未正式驗證，目前基準是 Unity Editor。

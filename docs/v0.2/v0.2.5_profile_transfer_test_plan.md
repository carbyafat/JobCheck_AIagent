# JobCheck V0.2.5 履歷資料搬遷測試說明

> 適用範圍：個人履歷母資料的獨立匯出、預覽與安全匯入
>
> 搬運檔：`.jobcheck-profile.json`

## 1. 測試前準備

1. 使用 Unity 2022.3.62f3 開啟 `Assets/Scenes/SampleScene.unity`。
2. 進入 Play Mode，從左側導覽切換到「履歷」。
3. 建立並儲存一份容易辨認的履歷，例如在自我介紹填入「裝置 A 測試」。
4. 關閉編輯畫面，確認顯示頁已重新載入剛才的內容。

履歷搬運和職缺頁的「資料搬運」互相獨立。請勿把 `.jobcheck.json` 當成履歷檔，也不要把 `.jobcheck-profile.json` 交給職缺搬運入口。

## 2. 匯出

1. 在履歷頁點「履歷搬遷」。
2. 點「匯出履歷」，從檔案選擇器指定資料夾與檔名。
3. 預期產生一個 `.jobcheck-profile.json`，畫面顯示完整路徑及匯出時間。
4. 再次選擇完全相同的檔名，預期不覆蓋原檔並顯示失敗。
5. 回到履歷頁，確認匯出前後的履歷內容沒有改變。

注意：搬運檔有完整性校驗，但尚未加密；不要公開分享真實履歷檔。

## 3. 空白裝置／空白資料區匯入

1. 將匯出檔複製到裝置 B，或先備份再移除 B 的 `personal_data/profile/profile.json` 製造空白情境。
2. 在 B 的履歷頁開啟「履歷搬遷」，點「選擇匯入檔」。
3. 預期畫面顯示來源路徑、匯出時間、各履歷區塊筆數，並提示本機尚無履歷。
4. 點「匯入履歷」。
5. 預期顯示匯入完成；關閉搬遷畫面後，履歷內容與 A 相同。
6. 停止並重新進入 Play Mode，確認履歷仍可從磁碟重新載入。

## 4. 相同履歷

1. 在已成功匯入的 B 再次選擇同一份搬運檔。
2. 預期顯示「與本機履歷相同」，匯入與取代按鈕皆不可用。
3. 確認 `profile.json` 沒有因重複操作而改變。

## 5. 不同履歷與取代備份

1. 在 B 編輯自我介紹為「裝置 B 本機內容」並儲存。
2. 再次選擇先前由 A 匯出的搬運檔。
3. 預期普通「匯入履歷」不可用，畫面明確警告本機已有不同履歷。
4. 不按取代，直接關閉；確認 B 的本機內容保持不變。
5. 重新預覽同一檔案，按「取代本機履歷」。
6. 預期匯入後顯示備份路徑，履歷內容改為 A 的版本。
7. 確認 `personal_data/profile_backups/` 內存在取代前的 JSON，且包含「裝置 B 本機內容」。

## 6. 失敗與取消

- 在檔案選擇器按取消：不應匯入或修改履歷。
- 選擇既有職缺 `.jobcheck.json`：應因副檔名／格式不符而拒絕。
- 將搬運檔複製一份並手動修改其中一個字：應因 SHA-256 校驗不符而拒絕。
- 將 `format_version` 改成未知值並重新計算校驗碼的測試 fixture：應顯示不支援版本。
- 匯入失敗後重新開啟履歷：原本本機資料仍應存在。

## 7. 自動測試涵蓋

- 履歷搬運副檔名與職缺搬運格式分離。
- SHA-256 不包含自身欄位，且履歷內容變更會改變校驗碼。
- 匯出不改來源、不覆蓋目的檔、不寫入個人資料目錄內。
- 預覽拒絕損毀檔案與未知格式版本。
- 空白目標建立、相同內容略過、不同內容未確認時拒絕。
- 明確取代前建立備份，寫入後由 Repository 重新載入核對。

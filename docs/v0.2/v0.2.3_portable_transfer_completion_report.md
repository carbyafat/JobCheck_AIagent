# JobCheck V0.2.3 個人資料搬運完成報告

> 功能狀態：已實作並完成同機人工驗收；待本批合併至本機 `main`
>
> 完成日期：2026-09-19
>
> Unity 基準：2022.3.62f3 LTS

## 1. 版本目標

V0.2.3 提供個人資料的單檔匯出、檔案選擇、驗證預覽與安全增量匯入。搬運檔包含公司、職缺、應徵及內嵌事件，使用 `.jobcheck.json` 副檔名與 SHA-256 完整性校驗；校驗碼不是加密或使用者身分驗證。

## 2. 已完成內容

- 個人資料可匯出為單一搬運檔，使用新檔名且不覆蓋既有匯出檔。
- 整合 SimpleFileBrowser，使用者可從檔案選擇器挑選搬運檔，不必手動輸入完整路徑。
- 空白資料區可完整還原；已有資料時按 ID 比對，只加入缺少的公司、職缺與應徵檔。
- 相同 ID 且內容一致時略過；相同 ID 但內容不同時整批拒絕，不覆蓋任一端資料。
- 原有職缺刪除改為移入本機垃圾桶，保留相關應徵與事件；公司資料維持不動。
- 垃圾桶提供清單、還原、單筆永久刪除與清空功能；永久操作需要二次確認。
- 正式垃圾桶按鈕與面板已存入 `AllJobPage.prefab`；一次性 Prefab Builder 已於生成後立即移除。

## 3. 驗收結果

- 使用者已人工確認職缺刪除正常。
- 使用者已人工確認垃圾桶還原、單筆永久刪除及清空垃圾桶正常。
- 使用者以「先匯出完整資料 → 刪除一筆 → 匯入原檔」製造差異，確認匯入只補回缺少的新資料。
- Persistence 專案在實作期間完成建置，結果為 0 警告、0 錯誤。
- 新增的 Persistence EditMode 測試已寫入專案；本輪未取得 Unity Test Runner 的完整機器可讀執行結果。

## 4. 安全邊界與已知限制

- 搬運檔尚未加密，也沒有個人身分標記；只能由使用者確認來源是自己的資料。
- 垃圾桶只保存在目前裝置，不隨搬運檔匯出。匯入也不傳播另一裝置的刪除狀態。
- 目前只合併全新的實體 ID。既有應徵新增事件、狀態變更或內容編輯會被視為同 ID 衝突，不進行逐欄位合併。
- 本次完成的是同機增量差異驗收；真正跨裝置仍需驗證作業系統路徑、權限與檔案複製流程。

## 5. 後續方向

若日後需要雙向同步，應先定義資料擁有者識別、刪除墓碑、衝突選擇與事件級合併規則，不能直接把目前的「只新增」擴充成靜默覆蓋。V0.2.4 原規劃的 AI Fit Score、摘要與面試準備不屬於本版範圍。

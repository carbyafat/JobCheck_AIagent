# JobCheck V0.2.6 1600×900 視窗測試說明

> 適用範圍：Windows 桌面版預設視窗與既有主要頁面的 16:9 等比例縮放

## 1. 設定目標

- 預設啟動尺寸：1600×900。
- 啟動模式：視窗模式，不使用全螢幕或原生螢幕解析度。
- 視窗不可自由縮放；本階段只承諾 1600×900。
- Canvas 保留 1920×1080 參考解析度，於 1600×900 以 `5/6` 等比例縮放，避免重新解讀既有 UI 座標。

## 2. Unity Game View 快速檢查

Player Settings 只影響建置後的程式視窗。若要在 Editor 預覽，請在 Game View 新增並選擇 `1600 × 900` 固定解析度，不要使用 Free Aspect。

依序確認：

1. 左側欄完整顯示，寬度約為畫面的八分之一，且不蓋住右側內容。
2. 「首頁／職缺／履歷」切換正常，頁面不會同時疊在一起。
3. 職缺列表的公司、職稱、狀態、薪資與底部按鈕沒有被裁切。
4. 開啟職缺詳細資料後，可正常捲動並返回列表。
5. 開啟 Filter、資料搬遷、垃圾桶、分析、新增職缺等視窗，確認按鈕和輸入欄仍在畫面內。
6. 履歷顯示、履歷編輯及履歷搬遷視窗均可正常操作，長文字區可以捲動。

## 3. Standalone Build 驗收

1. 建置 Windows 版本並啟動。
2. 確認程式以 1600×900 視窗開啟，而非全螢幕。
3. 確認視窗邊框不可拖曳改變尺寸。
4. 重做第 2 節的主要頁面與彈窗檢查。
5. 關閉後重新開啟，確認不會因作業系統記住舊尺寸而回到 1920×1080 或全螢幕。

## 4. 自動檢查涵蓋

- Player Settings 的預設寬、高、視窗模式與不可縮放設定。
- Canvas Scaler 保留 1920×1080 並以寬度匹配。
- 1600×900 與 1920×1080 的縮放比例一致，不產生上下黑邊或額外裁切。
- 職缺頁主要控制項換算到 1600×900 後仍位於側欄右側及視窗邊界內。

## 5. 本階段限制

- 尚未承諾 1366×768、非 16:9、視窗自由縮放或作業系統顯示縮放的完整支援。
- 若後續要支援多解析度，應另行處理彈窗最小尺寸、Scroll View、字級與側欄折疊，不直接沿用本次固定尺寸驗收結果。

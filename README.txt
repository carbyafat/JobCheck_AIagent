JobCheck
========

JobCheck 是以 Unity 製作的個人求職紀錄與應徵流程管理工具。V0.2.0 建立 Domain、DTO、Mapper、Repository 與 ApplicationEvent 架構；V0.2.1 讓它能安全承載個人真實求職資料；V0.2.2 加入唯讀應徵分析；V0.2.3 完成個人資料搬運與垃圾桶；V0.2.4 建立應用程式導覽及個人履歷母資料；V0.2.5 完成履歷的獨立跨裝置搬遷。


目前版本
--------

V0.2.5 功能已完成，新增：

- 將已儲存履歷匯出為獨立 `.jobcheck-profile.json`，由使用者選擇位置且不覆蓋既有檔案。
- 匯入前驗證檔案大小、格式版本、SHA-256、DTO 與 Domain，並預覽來源時間及各區塊筆數。
- 本機無履歷時建立、內容相同時略過；內容不同時必須明確選擇取代。
- 取代前將原始履歷備份至 `personal_data/profile_backups/`，寫入後重新載入核對。
- 履歷搬遷與公司／職缺／應徵搬運在檔案格式、服務及 UI 入口上維持分離。

V0.2.4 已完成的履歷基礎包括：

- 固定側欄與首頁、職缺、履歷三個主要頁面；既有職缺列表、詳細與返回流程維持不變。
- 個人履歷 Domain 模型、驗證、穩定 ID、DTO、Mapper 與獨立 Repository。
- 履歷顯示與編輯 UI，包含自我介紹、連結、技能、語言、工作經歷、專案與學歷。
- 履歷頁使用 TextMesh Pro 與繁體中文，並支援長文字、捲動與中文輸入法組字。
- 履歷資料儲存在 `personal_data/profile/profile.json`，不與職缺搬運格式混用。

V0.2.6 已建立共用 UI 視覺基礎，並以首頁儀表板提供職缺總數、進行中應徵、待檢視、長期未回覆、履歷完成狀態及常用操作入口；所有數字沿用既有 Analytics Query，不另建統計口徑。

V0.2.7 已加入本機規則式履歷比對：技能採明確別名正規化，工作年資以月計算並合併重疊區間，學歷同時判斷等級與完成狀態；結果區分符合、明確不符合、履歷未證明與職缺條件不明，衍生分數只在載入時即時計算，不寫回職缺 JSON。

V0.2.8 已建立求職條件頁與雙向比對基礎：目標職務、產業、薪資、地區、聘僱形式、工作模式與上班時段採可追溯規則比較；必要條件不符、部分符合及職缺未提供會分開呈現。通勤、加班、外派及搬遷暫時只保存為後續 AI 判斷上下文，不進入規則分數。

先前版本已完成的功能仍包括：

- Demo／個人資料隔離、完整的職缺輸入與事件追蹤流程。
- 唯讀應徵漏斗、來源平台、目前結果與結束原因分析。
- 公司、職缺與應徵資料的單檔匯出、檔案選擇、驗證預覽及只新增匯入。
- 個人職缺垃圾桶、還原、單筆永久刪除與清空垃圾桶。
- Domain 驗證錯誤集中翻譯為繁體中文，不直接向使用者顯示 enum 名稱。

真實資料目前仍由使用者人工整理與輸入，不包含平台爬取或自動匯入。完整紀錄位於 `docs/v0.2/` 下各版本完成報告。


開啟方式
--------

Unity 版本：2022.3.62f3 LTS

Unity 專案：

    AI Personal Job agent/

主要場景：

    Assets/Scenes/SampleScene.unity

基本操作：

1. 使用 Unity 2022.3.62f3 開啟專案。
2. 開啟 SampleScene 並進入 Play Mode。
3. 在總攬頁確認目前是 Demo 或個人資料，點擊資料標示可切換。
4. 按 Load 載入目前選取的資料區。
5. 可瀏覽、篩選、新增、編輯或刪除個人職缺。
6. 點擊職缺可查看詳細內容、補登應徵事件、設定追蹤日期與查看事件歷程。
7. 從職缺頁點「分析」，查看目前資料區的唯讀統計；可捲動內容並按「關閉」回到列表。
8. 使用左側導覽切換至「履歷」，可檢視、編輯並儲存個人履歷母資料。
9. 在履歷頁點「履歷搬遷」，可獨立匯出、預覽及安全匯入履歷資料。


V0.2 資料結構
--------------

儲存庫根目錄目前有兩套互相隔離的資料區：

- `data/`：納入版本控制的虛構 Demo 資料。
- `personal_data/`：本機個人資料，整個目錄由 `.gitignore` 排除。

兩套資料區的主要資料使用相同 V0.2 結構：

- `companies/`：公司主資料。
- `jobs/`：職缺主資料；以 `company_id` 關聯公司，不重複保存公司名稱。
- `applications/`：應徵資料及內嵌事件歷程。

`data/migration/` 另外保存 V0.1 demo migration 的備份與證據。個人職缺被刪除時會連同相關 Application 與事件移至 `personal_data/trash/`，可由垃圾桶 UI 還原或永久刪除。個人履歷母資料另存於 `personal_data/profile/profile.json`；匯入取代前的備份保存在 `personal_data/profile_backups/`。

已提交的資料全部是虛構 demo。Unity UI 日後產生的新 UUID JSON 預設只留在本機，不會自動進入 Git；正式 demo 清單與加入方式請見 `data/README.md`。


主要程式區域
------------

- `Assets/JobCheck/Runtime/`：Domain 模型、enum、ID、驗證與事件狀態推導。
- `Assets/JobCheck/Persistence/`：DTO、Mapper、Repository、migration、唯讀分析 query 與寫入服務。
- `Assets/JobCheck/Tests/`：Domain 與 Persistence EditMode tests。
- `Assets/Scripts/`：Unity UI 與 V0.2 顯示／操作接軌。
- `Assets/JobCheckUiTheme.asset`：UI 共用色票、字體角色、間距與元件尺寸規格。
- `docs/v0.2/`：V0.2 規則、migration 與完成紀錄。


測試
----

在 Unity 開啟：

    Window > General > Test Runner

選擇 EditMode 後執行 Run All。V0.2.0 的封版基準為 265 passed、0 failed；先前安全清理批次回報 296 passed、0 failed（未保留機器可讀結果檔）。V0.2.5 新增的 14 個履歷搬遷目標測試已在 Unity 隨附 Mono 執行並全部通過；履歷匯出、匯入、內容比對與取代也已由使用者人工驗收。


後續方向
--------

後續版本遵守以下原則：先保護及搬運使用者資料；一個版本只承擔一種主要風險；AI 產生內容與匯入資料都必須先預覽，不得靜默覆蓋母資料。

### V0.2.6：首頁摘要與 UI 視覺基礎

- 顯示職缺總數、進行中應徵、近期事件、履歷最後更新時間及空資料提示。
- 提供新增職缺、查看職缺、查看分析與編輯履歷的快捷入口。
- 重用既有 Repository 與 Analytics Query，不建立第二套統計口徑。
- 建立共用色票、字級、間距、按鈕、輸入框、卡片與 Modal 規格。
- 以首頁作為新視覺基準，再統一側欄、職缺列表、履歷頁與常用視窗。
- 首頁維持唯讀，並驗證 1920×1080 與較小解析度配置。

### V0.2.7：履歷與職缺比對基礎

- 先完成不依賴外部 AI、可重現且可測試的規則式比對。
- 正規化技能、經歷、語言與職缺需求，延用既有 Fit Score 共通契約。
- 年資統一以月比較並排除重疊區間；學歷比較最低等級、完成狀態與明確科系標籤。
- 區分「明確不符合」、「履歷未證明」和「職缺條件不明」，每個分數都能追溯到具體欄位。
- 預設即時計算，不先將衍生結果寫回職缺 JSON。

### V0.2.8：求職條件與雙向比對

- 在左側導覽新增「求職條件」頁，與履歷能力及單筆職缺資料分開管理。
- 記錄目標職務、產業、薪資、工作型態、地點／通勤、工時／加班、遠端與其他限制。
- 每項條件可標記為「必要」、「偏好」或「不在意」，並保留補充說明欄位。
- 將既有「履歷是否符合職缺」擴充為雙向結果，同時顯示「職缺是否符合求職條件」。
- 規則式結果必須可追溯；必要條件不符、偏好加減分及資料不足應分開呈現。

### V0.2.9：AI 求職輔助

- 在規則式比對結果上產生職缺摘要、履歷亮點、差距說明與面試準備題目。
- 先定義 AI Provider、金鑰設定、送出資料預覽、取消與錯誤處理。
- AI 結果不得自動改寫履歷或職缺母資料；沒有 API 或額度時，既有功能仍可使用。
- 開工前必須確認個人資料送出範圍、同意流程、保存與刪除規則。

### V0.3.0：履歷文件輸出

- 將個人履歷母資料轉成給公司看的文件，與 JobCheck 可重新讀取的搬運檔明確區分。
- 先提供區塊選擇與預覽；建議先完成 PDF，再評估可編輯 DOCX。
- 驗證中文字型、長文字、長網址、分頁與空白區塊隱藏。

### V0.3.1：外部職缺帶入

- 第一階段先支援貼上職缺文字或網址，不直接承諾網站爬取。
- AI 或解析器只產生結構化草稿，使用者預覽、修正及確認後才建立正式職缺。
- 加入必填驗證、可能重複職缺與來源 URL 檢查。
- 個別網站自動取得需另外評估登入、版面變動、反自動化機制與使用條款。

### 長期候選項目

- 真正的雙向同步：裝置／擁有者識別、刪除墓碑、衝突選擇與事件級合併。
- 他人履歷或匿名資料比較：獨立資料邊界、來源標記與隱私刪除規則。
- 多份履歷版本、技能同義詞維護、加密備份與密碼保護。
- 分析圖表：只有文字報表確實不足以判讀時再加入。
